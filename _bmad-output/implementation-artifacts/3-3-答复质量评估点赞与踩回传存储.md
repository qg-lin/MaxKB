## Story

As a 终端最终用者,
I want 对产生的每一条问答流回复做单点 Thumbs-up（赞）或 Thumbs-down（踩）的点击,
so that 我的感受和对准确率的纠正意图留档下来帮助后台的工程师做长期调优.

## Acceptance Criteria

1. **Given** 某条流式对话消息已经处于呈现完毕的状态，**When** 我点击了赞或者踩按钮，**Then** UI 端发起一个只读状态翻转的异步请求至后台，**And** 相关的历史记录表中的 `vote_status` 一列将持久化保存此次点击结果（初始为 `-1`，赞为 `0`，踩为 `1`）。
2. **Given** 用户处于未投票状态（`vote_status = "-1"`），**When** 点击赞或踩，**Then** 弹出原因选择面板（桌面端为 Popover，移动端为 Drawer），用户可选择原因后提交。
3. **Given** 用户已完成投票（`vote_status = "0"` 或 `"1"`），**When** 再次点击对应按钮（此时显示彩色图标），**Then** 系统发起取消投票请求，`vote_status` 重置为 `"-1"`，`vote_reason` 和 `vote_other_content` 清空。
4. **Given** 用户已完成投票，**When** 尝试再次以不同类型投票（不先取消），**Then** 后端返回错误"已投票，请先取消后再投"。
5. **Given** 并发投票请求，**When** 同一 `chat_record_id` 的多个并发请求到达，**Then** Redis 分布式锁保证只有一个请求处理成功，其他返回错误。

> **⚠️ 字段说明**：PRD/Epics 原文提及 `feedback_type` 字段，但实际生产代码中已落地实现使用的是 `vote_status` 字段（`VoteChoices: -1=未投票, 0=赞同, 1=反对`）。这是有意的实现决策，本故事以实际代码字段为准。

class VoteChoices(models.TextChoices):
    UN_VOTE = "-1", '未投票'   # 默认状态
    STAR    = "0",  '赞同'
    TRAMPLE = "1",  '反对'

class VoteReasonChoices(models.TextChoices):
    ACCURATE   = 'accurate',   '内容准确'   # 赞同原因
    COMPLETE   = 'complete',   '内容完善'   # 赞同原因
    INACCURATE = 'inaccurate', '内容不准确' # 反对原因
    INCOMPLETE = 'incomplete', '内容不完善' # 反对原因
    OTHER      = 'other',      '其他'       # 反对原因（附加文本）

#### `VoteSerializer.vote()` 状态机逻辑（第 50-99 行）

```python
@transaction.atomic
def vote(self, instance: Dict, with_valid=True):
    rlock = RedisLock()
    if not rlock.try_lock(self.data.get('chat_record_id')):
        raise AppApiException(500, "Voting ... please do not send repeated requests")
    try:
        chat_record = QuerySet(ChatRecord).get(
            id=self.data.get('chat_record_id'),
            chat_id=self.data.get('chat_id')
        )
        vote_status = instance.get("vote_status")

        if chat_record.vote_status == VoteChoices.UN_VOTE:
            # 投票：保存 vote_status + vote_reason + vote_other_content
            if vote_status in [VoteChoices.STAR, VoteChoices.TRAMPLE]:
                chat_record.vote_status = vote_status
                chat_record.vote_reason = instance.get("vote_reason")
                chat_record.vote_other_content = instance.get("vote_other_content") or ''
            chat_record.save()
        else:
            if vote_status == VoteChoices.UN_VOTE:
                # 取消投票
                chat_record.vote_status = VoteChoices.UN_VOTE
                chat_record.vote_reason = None
                chat_record.vote_other_content = ''
                chat_record.save()
            else:
                raise AppApiException(500, "Already voted, please cancel first and then vote again")
    finally:
        rlock.un_lock(self.data.get('chat_record_id'))
    ChatCountSerializer(data={'chat_id': self.data.get('chat_id')}).update_chat()
    return True
```

### 架构约束与强制规则

参见 `_bmad-output/planning-artifacts/architecture.md` 与 `_bmad-output/project-context.md`：

1. **鉴权模式**：`VoteView` 使用 `ChatTokenAuth`（终端用户 token），非管理员 `SessionAuthentication`。前端通过 `/chat/request` 封装的 `put()` 自动附带 Bearer Token。
2. **并发保护**：`RedisLock` 是必须的，禁止移除。高并发场景下重复投票是真实风险。
3. **事务保证**：`@transaction.atomic` 包裹整个 `vote()` 方法，确保 DB 写入与计数器更新原子性。
4. **API 调用封装**：`vote()` 必须通过 `ui/src/api/chat/chat.ts` 封装调用，禁止在 Vue 组件内直接调用 fetch/axios。
5. **命名规范**：后端字段 `vote_status`、`vote_reason`、`vote_other_content` 均为 `snake_case`；前端接收后直接映射（无需 camelCase 转换）。
6. **`vote_reason` 可空**：点赞时 `vote_reason` 可以不选（可选字段），踩时同样可选但设计上建议选择。
7. **前端状态同步**：投票成功后必须通过 `emit('update:data')` 同步父组件状态，不能仅依赖本地 `buttonData.value`。

### 关键风险与注意事项

1. **`write_ed` 状态**：`ChatOperationButton.vue` 中投票按钮有 `:disabled="!data?.write_ed"` 控制。`write_ed` 在 SSE 流结束后设置为 `true`（Story 3.1 修复后可靠）。需确认 `data.write_ed` 何时被设置。
2. **`type` 限制**：操作按钮仅在 `type == 'ai-chat' || type == 'log'` 时显示赞踩按钮（见第 42 行 `v-if`），`debug-ai-chat` 模式不显示投票按钮。
3. **`closingPopover` 调用**：`closePopover()` 同时关闭 `likePopoverRef` 和 `opposePopoverRef`，需确认两个 ref 在组件销毁前都已正确初始化（避免 undefined 错误）。
4. **Redis 连接可用性**：`RedisLock` 依赖 Redis 服务。本地开发环境若 Redis 未启动，投票 API 会抛出连接错误，需在测试中 mock RedisLock。
5. **`ChatCountSerializer.update_chat()` 副作用**：投票后会更新 `Chat.star_num/trample_num` 统计数据，取消投票同样触发。需确认计数器不会出现负数（取消投票时减少计数）。
6. **`vote_other_content` 长度**：最大 1024 字符，前端 `VoteReasonContent.vue` 的 textarea 需有对应限制，避免后端截断。
