# Story 1.1: 多格式本地文档上传与网页抓取集成

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 知识管理员,
I want 能在系统内通过拖拽或选择的方式上传 PDF、Word 等格式的文档，并能输入指定 URL 让系统抓取内容,
so that 能将企业现有的分散且格式不一的知识资产统一汇入到知识库中心化管理.

## Acceptance Criteria

1. **Given** 我处于知识库创建/编辑界面
   **When** 我选择上传一个 10MB 的 PDF 或输入一个合规的 URL 网页
   **Then** 系统应该能够接收这些文件或请求，并显示入库进度状态
   **And** 前端必须显示 loading 状态直到通过 Axios 拦截器确认接收成功

**状态编码**（`Status` 类解析 `document.status` 字符串）：

```python
class State(Enum):
    PENDING  = '0'  # 等待处理
    STARTED  = '1'  # 执行中
    SUCCESS  = '2'  # 成功
    FAILURE  = '3'  # 失败
    REVOKE   = '4'  # 取消任务
    REVOKED  = '5'  # 取消成功
    IGNORED  = 'n'  # 忽略

class TaskType(Enum):
    EMBEDDING        = 1  # 向量化任务
    GENERATE_PROBLEM = 2  # 生成问题任务
    SYNC             = 3  # 同步任务
```

**`KnowledgeType` 枚举**（`document.type` 和 `knowledge.type` 使用）：
- `BASE = 0`：普通本地文档（PDF/Word/TXT 等）
- `WEB = 1`：网页抓取文档
- `LARK = 2`：飞书类型
- `WORKFLOW = 4`：工作流类型

**`Knowledge` 限制字段**（创建文档前需校验）：
- `file_size_limit = 100`（MB，默认值）
- `file_count_limit = 50`（文件数量限制，默认值）

### 🗂 已支持的文件格式（后端 split_handles 链）

```python
# apps/knowledge/serializers/document.py 第 67-77 行
split_handles = [
    HTMLSplitHandle(),   # .html, .htm
    DocSplitHandle(),    # .doc, .docx (Word)
    PdfSplitHandle(),    # .pdf
    XlsxSplitHandle(),   # .xlsx
    XlsSplitHandle(),    # .xls
    CsvSplitHandle(),    # .csv
    ZipSplitHandle(),    # .zip（批量上传打包）
    TextSplitHandle(),   # .txt, .md 及其他文本（兜底）
]
```

**文件选择机制**：每个 Handle 实现 `support(file_name, content_type)` 方法，按顺序匹配第一个支持的 Handler。前端上传时 `accept` 属性需包含以上格式。

**文件存储机制**：
- 文件通过 `File.save(bytea=...)` 写入 PostgreSQL Large Object（`loid`）
- 相同 SHA256 hash 文件自动复用同一 `loid`（去重）
- 文件以 ZIP 压缩格式存储（减少存储空间）
- **前端无需实现分片上传** - 后端 Large Object 支持流式写入

```python
# 创建网页文档的完整调用链：
# 1. 前端 POST /knowledge/{id}/document/web

```

**网页文档特征**：
- `document.type = KnowledgeType.WEB (1)`
- `document.meta['source_url']` 存储原始 URL
- 支持定时同步（通过 `/sync` 接口）

### ⚡ 文件解析与入库流程（核心安全约束）

```
前端上传文件
  ↓
POST /document（MultiPartParser 接收）
  ↓
DocumentSerializers.Create.save()
  ↓
选择对应 split_handle → 解析文本内容 → 切分为 Paragraph 列表
  ↓
@transaction.atomic
  ├── 创建 Document ORM 记录（status=PENDING）
  ├── 创建 Paragraph ORM 记录（批量写入）
  └── File.save(bytea) → PostgreSQL Large Object
  ↓
ListenerManagement.embedding_by_document_signal(document_id)
  ↓（异步）
Celery: embedding_by_document() → models_provider → 向量化 → 写入 Embedding 表
```

**关键约束**：
- 🔴 长事务（Embedding）必须在 Celery 中执行，**绝不在 HTTP 进程中阻塞**
- 🔴 大模型 Embedding 必须通过 `apps/models_provider/` 调用，**不得硬编码供应商**
- 🔴 前端在 POST 返回后立即展示"向量化进行中"的状态（轮询 `document.status`）
