# Story 7.2: 表单收集后端 - 运行时解析文本字段引用变量并注入默认值

Status: done

## Story

As a 编排工程师,
I want 配置了"引用变量"赋值方式的 TextInput/TextareaInput 字段，在工作流执行时能自动解析并填入上游节点的实际输出值,
so that 终端用户打开表单时看到的默认值是根据当前流程上下文动态生成的，而不是一个固定字符串.

## Acceptance Criteria

1. **Given** "表单收集"节点中存在 `default_value_assignment_method == 'ref_variables'` 的 TextInput 或 TextareaInput 字段
   **When** 工作流执行到该节点、`reset_field()` 方法被调用时
   **Then** 后端识别该字段类型及赋值方式，调用 `workflow_manage.get_reference_field(field['default_value'][0], field['default_value'][1:])` 解析变量路径，将返回值转为字符串后赋给 `field['default_value']`

2. **And** 若解析结果为 None 或非字符串类型，回退为空字符串 `''`，不抛出异常，不中断流程执行

3. **And** `default_value_assignment_method == 'custom'`（或该字段不存在）的 TextInput/TextareaInput 字段行为与改动前完全一致，不受影响

4. **And** 改动仅限于 `apps/application/flow/step_node/form_node/impl/base_form_node.py` 的 `reset_field()` 方法，不修改其他节点类型的处理逻辑

**关键：阶段1 循环对 TextInput 引用变量模式的安全性分析：**

当 `default_value_assignment_method == 'ref_variables'` 时，`field['default_value']` 是数组格式 `[nodeId, ...path]`（由 Story 7.1 前端写入）。

循环处理 `f == 'default_value'` 时：
- `_value = [nodeId, ...path]`（数组）
- `if _value is None` → False，跳过
- `if isinstance(_value, str)` → False，跳过
- `elif f == 'label'` → False，跳过
- 最终**不做任何操作**，数组原样保留 ✓

因此阶段1不会破坏引用变量格式，我们可以安全地在阶段3之后添加新逻辑。

**改动后完整的 `reset_field()` 方法：**

```python
def reset_field(self, field):
    reset_field = ['field', 'label', 'default_value']
    for f in reset_field:
        _value = field[f]
        if _value is None:
            continue
        if isinstance(_value, str):
            field[f] = generate_prompt(self.workflow_manage, _value)
        elif f == 'label':
            _label_value = _value.get('label')
            _value['label'] = generate_prompt(self.workflow_manage, _label_value)
            tooltip = _value.get('attrs').get('tooltip')
            if tooltip is not None:
                _value.get('attrs')['tooltip'] = generate_prompt(self.workflow_manage, tooltip)

    if ['SingleSelect', 'MultiSelect', 'RadioCard', 'RadioRow', 'MultiRow'].__contains__(field.get('input_type')):
        if field.get('assignment_method') == 'ref_variables':
            option_list = self.workflow_manage.get_reference_field(field.get('option_list')[0],
                                                                   field.get('option_list')[1:])
            option_list = option_list if isinstance(option_list, list) else []
            field['option_list'] = option_list
            field['default_value'] = get_default_option(option_list, field.get('input_type'),
                                                        field.get('value_field'))

    if ['JsonInput'].__contains__(field.get('input_type')):
        if field.get('default_value_assignment_method') == 'ref_variables':
            field['default_value'] = self.workflow_manage.get_reference_field(field.get('default_value')[0],
                                                                              field.get('default_value')[1:])

    if ['TextInput', 'TextareaInput'].__contains__(field.get('input_type')):
        if field.get('default_value_assignment_method') == 'ref_variables':
            ref_value = self.workflow_manage.get_reference_field(
                field['default_value'][0], field['default_value'][1:])
            field['default_value'] = ref_value if isinstance(ref_value, str) else ''

    return field
```

### 与 JsonInput 实现的关键差异

| 对比点 | JsonInput（第102-105行，现有） | TextInput/TextareaInput（本故事，新增） |
|--------|-------------------------------|----------------------------------------|
| 字段名 | `default_value_assignment_method` | `default_value_assignment_method`（相同）|
| 解析调用 | `get_reference_field(...)` | `get_reference_field(...)`（相同）|
| 结果处理 | 直接赋值（任意类型） | **强制要求字符串类型**，非字符串回退为 `''` |
| None 处理 | 直接赋 None（可能导致前端异常） | 回退为 `''`（安全） |

**为什么 TextInput 需要字符串强制类型转换：**
文本字段在前端渲染时直接用作 `el-input` 的值，必须是字符串。而 JsonInput 存储的是 JSON 对象，其类型无约束。

### 前端数据结构（Story 7.1 输出的字段格式）

Story 7.1 实现后，`default_value_assignment_method == 'ref_variables'` 模式下前端发送的字段 JSON：

```json
{
  "input_type": "TextInput",
  "attrs": { "maxlength": 200, "minlength": 0, "show-word-limit": true },
  "default_value": ["nodeId_abc", "output", "fieldName"],
  "show_default_value": true,
  "default_value_assignment_method": "ref_variables",
  "props_info": { "rules": [...] }
}
```

`field['default_value'][0]` = `"nodeId_abc"`（节点 ID）
`field['default_value'][1:]` = `["output", "fieldName"]`（字段路径）

### `get_reference_field` 方法说明

`self.workflow_manage.get_reference_field(node_id, field_path_list)` 是工作流管理器的标准方法，用于从执行上下文中查找指定节点的输出字段值。

- 若节点已执行且字段存在 → 返回对应值（类型取决于上游节点输出，通常为字符串）
- 若节点未执行或字段不存在 → 返回 `None`
- 该方法自身不抛异常，调用安全

参考现有调用模式（`JsonInput` 第103-105行、`SingleSelect` 第94-96行），可直接复用相同调用方式。

### 回归安全性分析

**不影响的场景：**

| 场景 | 原因 |
|------|------|
| `TextInput` + `custom`（或无 `default_value_assignment_method`） | `field.get('default_value_assignment_method') == 'ref_variables'` 为 False，跳过整块逻辑 |
| `TextInput` + `default_value` 为字符串（旧数据无此字段） | 同上，条件不满足，跳过 |
| 其他节点类型（SingleSelect、MultiSelect、JsonInput 等） | `field.get('input_type')` 不在 `['TextInput', 'TextareaInput']` 中，跳过 |
| 阶段1的字符串模板渲染循环 | 当 `default_value` 为数组时，循环分支全部不匹配，不做任何操作 |
