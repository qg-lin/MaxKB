# Story 6.2: 联邦治理下的知识合规共享穿透配置

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 多租户群管理,
I want 设置特定的跨组织特权通道让在租客A生成的"公共规定类知识库"可以被授权给其他租户读调用使用,
so that 既保护敏感又规避集团重复维护通用公共资产引发的冗余工作.

## Acceptance Criteria

1. **AC1 - EE 版本守卫**：所有知识库共享作用域配置 API（设置 scope、查看授权、管理白名单）仅限 EE 版本可用。CE/PE 版本调用返回 HTTP 403 + 版本不支持提示。`GET /workspace/{workspace_id}/shared_knowledge` 在 CE/PE 版本返回空列表（优雅降级，不报错）。

2. **AC2 - 知识库 scope 设置（所属 Workspace 管理员）**：
   - `GET /workspace/{workspace_id}/knowledge/{knowledge_id}/scope` → 获取当前知识库的共享配置（`scope`、`authentication_type`、`workspace_id_list`）
   - `PUT /workspace/{workspace_id}/knowledge/{knowledge_id}/scope` → 设置知识库共享模式：
     - `scope=WORKSPACE`：仅当前 Workspace 可用（默认，关闭共享）
     - `scope=SHARED` + `authentication_type=ALL_ACCESS`：全开放，所有 Workspace 均可读（`workspace_id_list` 作为黑名单，列表内的 Workspace 被排除）
     - `scope=SHARED` + `authentication_type=WHITE_LIST`：仅白名单内的 Workspace 可读（`workspace_id_list` 列出被授权的 Workspace ID）
   - 此接口仅限知识库所属 Workspace 的 ADMIN 或 WORKSPACE_MANAGE 角色调用。外部 Workspace 不得调用。

3. **AC3 - 跨租户共享知识库列表**：
   - `GET /workspace/{workspace_id}/shared_knowledge` → 返回当前 Workspace 有权读取的所有来自其他 Workspace 的共享知识库列表
   - 返回字段包含：`id`、`name`、`desc`、`scope`（固定为 `SHARED`）、`source_workspace_id`、`create_time`
   - CE/PE 版本返回空列表 `[]`，不返回错误

4. **AC4 - 跨租户知识库只读穿透**：
   - `GET /workspace/{workspace_id}/shared_knowledge/{knowledge_id}` → 跨租户读取共享知识库详情
   - `GET /workspace/{workspace_id}/shared_knowledge/{knowledge_id}/document/{current_page}/{page_size}` → 跨租户分页读取文档列表（只读）
   - `GET /workspace/{workspace_id}/shared_knowledge/{knowledge_id}/document/{document_id}/paragraph/{current_page}/{page_size}` → 跨租户分页读取段落（只读）
   - 上述所有 GET 接口在调用前须验证：当前 Workspace 是否在该知识库的授权列表中（WHITE_LIST 模式），或未被排除（ALL_ACCESS 模式）

5. **AC5 - 写操作强制阻断**：
   - 对来自非所属 Workspace 的任何 PUT/POST/DELETE 请求到共享知识库资源（文档、段落、知识库本身），后端必须返回 HTTP 403 + 错误提示"无权对共享知识库进行写操作"，不得穿透执行。
   - 此规则适用于所有已存在的文档/段落/知识库修改端点，需在序列化器层校验 `workspace_id` 是否为知识库所属 Workspace。

6. **AC6 - `KnowledgeWorkspaceAuthorization` 模型注册（EE）**：
   - 该模型仅在 EE 模式下通过 `DatabaseModelManage` 注册，key 为 `knowledge_workspace_authorization`
   - CE 模式 `DatabaseModelManage.get_model("knowledge_workspace_authorization")` 返回 `None`，共享功能优雅降级
   - 模型与 `Knowledge` 表通过 `knowledge_id`（UUID）关联，且关联是 `OneToOne` 形式（知识库只有一条授权配置记录）

7. **AC7 - 应用编排器知识选择器联动**（已有代码，须验证不回归）：
   - `application/serializers/application.py` 中已有跨租户共享知识库查询逻辑（约 L1173-L1185），本 Story 的模型更改须确保该逻辑继续正常工作
   - 已有逻辑：WHITE_LIST 时 workspace_id 须在 `workspace_id_list` 中；ALL_ACCESS 时 workspace_id 须不在 `workspace_id_list` 中（黑名单逻辑）

### 📐 `KnowledgeWorkspaceAuthorization` EE 模型结构（须在 EE 模块创建）

```python
# 路径：EE模块内（非 apps/ 目录）
from django.contrib.postgres.fields import ArrayField
from django.db import models
import uuid_utils.compat as uuid
from common.mixins.app_model_mixin import AppModelMixin

class KnowledgeWorkspaceAuthorization(AppModelMixin):
    """
    知识库跨 Workspace 授权配置表（EE Only）
    - WHITE_LIST 模式：workspace_id_list 为白名单（被授权的 workspace）
    - ALL_ACCESS 模式：workspace_id_list 为黑名单（被排除的 workspace）
    """
    id = models.UUIDField(primary_key=True, default=uuid.uuid7, editable=False)
    knowledge_id = models.UUIDField(unique=True, db_index=True, verbose_name="知识库ID")
    authentication_type = models.CharField(
        max_length=20,
        choices=[('WHITE_LIST', '白名单'), ('ALL_ACCESS', '全开放')],
        default='ALL_ACCESS',
        verbose_name="授权类型"
    )
    workspace_id_list = ArrayField(
        base_field=models.CharField(max_length=128),
        default=list,
        verbose_name="Workspace ID 列表"
    )

    class Meta:
        db_table = "knowledge_workspace_authorization"
```

### ⚠️ 关键陷阱与防护

1. **`id__in=inner` 的子查询陷阱**：`application.py` 中 `QuerySet(Knowledge).filter(id__in=inner)` 使用了 auth_model 的 queryset 作为子查询。若 auth_model 的 PK（`id`）不等于 `knowledge_id`，这将产生错误结果。开发时必须先确认 EE 模块中 `KnowledgeWorkspaceAuthorization.id` 的真实定义再写查询代码，或改用 `.values_list('knowledge_id', flat=True)` 来明确指定字段。

2. **不得使用 `knowledge.workspace_id` 作为跨租户访问控制**：`workspace_id` 是知识库所属方，不是请求方。所有跨租户权限检查必须通过 `knowledge_workspace_authorization` 表验证，而非直接比对 `workspace_id`。

3. **`scope=WORKSPACE` 时删除授权记录**：将知识库改回 `WORKSPACE` 作用域时，须同时删除 `KnowledgeWorkspaceAuthorization` 记录并将 `Knowledge.scope` 改回 `WORKSPACE`，否则残留记录可能导致该知识库继续出现在其他租户的共享列表中。

4. **并发 `update_or_create` 安全**：`KnowledgeWorkspaceAuthorization` 的 `knowledge_id` 字段有 `unique=True` 约束，并发时可能触发唯一约束异常，须用 `update_or_create(knowledge_id=kid, defaults={...})` + `IntegrityError` 捕获处理。

5. **写操作阻断必须在序列化器层执行**：不能仅靠 URL 路由区分读写（共享路径 `/shared_knowledge/` 与原路径 `/knowledge/` 均可操作文档），必须在现有写方法中增加 `workspace_id` 所有权校验，防止直接访问 `/workspace/{外部id}/knowledge/{共享kid}/document/` 路径的越权写入。

6. **`workspace_id_list` 数据类型**：存储的是 Workspace ID（字符串），注意与历史数据中的 `"default"` workspace 兼容。
