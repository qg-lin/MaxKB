# Story 1.2: 文档自动向量化与智能自适应分段

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 知识管理员,
I want 在上传文档后触发后端的全自动化抽取、切片分段与 Embedding 向量转换,
so that 不需要我人工去标注文档重点，系统即可把原本长篇大论的文件转化为适合检索的独立小段落.

## Acceptance Criteria

1. **Given** 知识库中已经上传了原始文档任务
   **When** 系统调度器开始处理该入库任务时
   **Then** Celery 应该在后台执行长事务将其切分为块状文本
   **And** 将文本片段送往大模型做 Embedding 操作，并将结果存入 PostgreSQL 的 pgvector 字段中

2. **Given** 文档正处于 Embedding 处理过程中
   **When** 前端轮询文档详情接口时
   **Then** `document.status` 应反映当前任务进度（`PENDING/STARTED/SUCCESS/FAILURE`）
   **And** 处理完成后前端应自动刷新状态并展示最终结果

3. **Given** 后端已为文档完成了切片
   **When** 分段数量写入数据库时
   **Then** 每条 `Paragraph` 记录含 `title`、`content`、`keywords` 字段
   **And** 同时写入 `Embedding` 向量记录到 pgvector 字段

```

  ↓
DocumentSerializers.Create.save()  [同步阶段]
  ├── split_handles 链选择合适 Handler
  │   ├── HTMLSplitHandle  → BeautifulSoup 提取文本
  │   ├── DocSplitHandle   → python-docx 提取段落
  │   ├── PdfSplitHandle   → PDF 文本提取
  │   ├── XlsxSplitHandle  → Excel 结构化提取
  │   ├── CsvSplitHandle   → CSV 行级提取
  │   ├── ZipSplitHandle   → 解压批量处理
  │   └── TextSplitHandle  → TXT/MD（兜底 Handler）
  │
  ├── SplitModel.parse(text)         ← 智能分段
  │   ├── parse_to_tree()            ← 识别 Markdown 标题层级
  │   ├── smart_split_paragraph()    ← 智能断句（优先级: 句号 > 感叹号 > 回车）
  │   └── 返回: [{title, content, keywords, parent_chain}]
  │
  ├── @transaction.atomic            ← 以下操作在同一事务中
  │   ├── Document.save()            ← 创建文档记录（status='0nn'=PENDING）
  │   ├── Paragraph.bulk_create()    ← 批量写入分段记录
  │   └── File.save(bytea=...)       ← PostgreSQL Large Object 存储原文
  │
  └── 返回 HTTP 200 → 前端立即收到响应

  ↓（异步）
ListenerManagement.embedding_by_document_signal(document_id)
  ↓
Celery: embedding_by_document.delay(document_id, model_id)  [QueueOnce 去重]
  ├── get_embedding_model(model_id)  ← ModelManage 缓存模型实例
  ├── ListenerManagement.embedding_by_document()
  │   └── PGVector._batch_save(text_list, embedding_model)
  │       ├── embedding.embed_documents(texts)  ← 调用大模型 Embedding API
  │       ├── Embedding.bulk_create()           ← 批量写入 pgvector 字段
  │       └── 更新 document.status → SUCCESS('2nn')
  │
  └── 异常时: document.status → FAILURE('3nn')
```

### 📊 向量化状态轮询机制（前端实现要求）

```typescript
// ui/src/api/knowledge/document.ts 中应封装的状态轮询工具

// 获取文档详情（含最新 status）
getDocumentDetail(knowledge_id, document_id, loading?)
// → GET /workspace/{workspace_id}/knowledge/{knowledge_id}/document/{document_id}

// 状态解析工具函数（前端需实现）:
function parseDocumentStatus(status: string): {
  embedding: 'pending' | 'started' | 'success' | 'failure' | 'ignored'
} {
  // status 字符串从右往左读，第1位（index -1）= embedding 状态
  const embeddingCode = status?.slice(-1) ?? 'n'
  const stateMap = { '0': 'pending', '1': 'started', '2': 'success', '3': 'failure', 'n': 'ignored' }
  return { embedding: stateMap[embeddingCode] ?? 'pending' }
}

// 推荐轮询模式:
function pollDocumentStatus(knowledgeId: string, documentId: string) {
  const timer = setInterval(async () => {
    const res = await getDocumentDetail(knowledgeId, documentId)
    const { embedding } = parseDocumentStatus(res.data.status)
    if (['success', 'failure', 'ignored'].includes(embedding)) {
      clearInterval(timer)  // 终止态：停止轮询
      // 更新 UI 状态
    }
    // PENDING/STARTED → 继续轮询（建议 3 秒间隔）
  }, 3000)
}
```

### 向量化链路的性能约束（来自 PRD NFR）

- **NFR2**: 1 亿 Token 单域向量召回必须 < 1 秒
- 因此 `PGVector._batch_save()` 使用 `Embedding.bulk_create()` 而非逐条 `save()`
- `search_vector` 字段（PostgreSQL 全文检索）在批量写入时使用 `SearchVector(Value(...))` 表达式
- **禁止**在 `apps/knowledge/vector/pg_vector.py` 中改为逐条写入，会严重劣化性能

### 前端轮询的内存安全要求

```vue
<script setup lang="ts">
import { onUnmounted } from 'vue'

const pollingTimers = new Map<string, ReturnType<typeof setInterval>>()

function startPolling(documentId: string) {
  if (pollingTimers.has(documentId)) return  // 防重复启动
  const timer = setInterval(async () => {
    // ... 轮询逻辑
    if (isTerminalState(status)) {
      clearInterval(timer)
      pollingTimers.delete(documentId)
    }
  }, 3000)
  pollingTimers.set(documentId, timer)
}

// 🔴 必须：组件销毁时清理所有计时器
onUnmounted(() => {
  pollingTimers.forEach(timer => clearInterval(timer))
  pollingTimers.clear()
})
</script>
```
