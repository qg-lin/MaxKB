## Epic 摘要

**Epic 7: 表单收集节点动态变量绑定增强 (Form Node Dynamic Variable Binding)**

编排工程师在配置"表单收集"节点时，能够为单行文本（TextInput）和多行文本（TextareaInput）字段选择"引用变量"赋值方式，将字段默认值与工作流上游节点的输出动态绑定，使表单预填内容随流程上下文自动适配。

## 做得好的（What Went Well）

1. **模式复用策略成功** — 严格参照 `JsonInputConstructor.vue` 现有模式移植到 TextInput 和 TextareaInput，零自创风险，实现又快又稳
2. **前后端解耦清晰** — Story 7.1 只改前端构造器，Story 7.2 只改后端运行时解析，两个 Story 完全独立，可分别实现和验证
3. **Code Review 有效** — 捕获了赋值方式切换时 `default_value` 类型残留（string vs array）的潜在 UX Bug，以及 `v-for` 缺少 `:key` 绑定，均已即时修复
4. **验收标准具体明确** — 每条 AC 都明确到字段名和数据结构，开发和验证无歧义
5. **防御性编程到位** — Story 7.2 对 `None` 和非字符串类型做了回退处理（`''`），比 JsonInput 现有实现更健壮

## 需改进的（What Could Be Improved）

1. **手动验证测试全部未执行** — Story 7.1 有 4 项、Story 7.2 有 5 项手动验证子任务未完成，共 9 项待验证
2. **缺乏自动化测试覆盖** — 项目缺少前端测试框架（架构文档标注为中优先级缺口），无法回归验证
3. **改进模式未反向推广** — Story 7.2 发现的 None 防御模式优于 JsonInput 现有实现，但未反向修复
4. **未做跨组件排查** — Code Review 发现的 `:key` 缺失和数据残留问题，可能影响其他构造器组件
5. **Sprint 状态管理不严谨** — Epic 7 全部 Story 完成但状态仍为 `in-progress`

---

## 关键洞察

1. **模式复用是最高效的开发策略** — 当有良好的参考实现时，新增功能几乎可以零摩擦交付。团队应持续维护"参考实现索引"
2. **Code Review 是当前唯一的质量关卡** — 它有效捕获了问题，但不能替代运行时验证。需要建立多层质量保障
3. **防御性编程值得推广** — Story 7.2 的 None 回退模式是一个值得在整个 `reset_field()` 方法中统一的改进
4. **手动验证不能跳过** — 必须在标记 done 前至少完成一轮冒烟测试
