# Story 5.4: 全链路不可逆审计日志搜集

Status: done

## Story

As a 企业合规审计员,
I want 能在后台面板查看、筛选或导出带时间戳的所有敏感管理操作（如删除模型、重制工作流、改变用户权限）的审计日志,
so that 合规检查能够定责并溯源每一个风险指令是由谁操作出来的.

## Acceptance Criteria

1. **AC1 - 日志分页查询**：`GET /operate_log/{current_page}/{page_size}` 返回分页数据，支持 `start_time`、`end_time`、`user`（用户名模糊搜索）、`status`（200/500）、`ip_address`（精确匹配）、`menu`（JSON 数组多选）、`workspace_ids`（JSON 数组，EE 版）等查询参数。返回格式 `{ "code": 200, "data": { "total": N, "records": [...] } }`。

2. **AC2 - 菜单操作选项获取**：`GET /operate_log/menu_operation_option/` 返回所有 Log 记录中已存在的 menu 去重列表（包含 `menu` 原始值和 `menu_label` 国际化标签），供前端筛选下拉框使用。

3. **AC3 - 日志导出 Excel**：`POST /operate_log/export/` 接受与分页查询相同的筛选参数，以流式响应返回 `.xlsx` 文件（使用 `openpyxl` 的 write_only 模式），包含列：操作菜单、操作详情、操作对象、用户、状态、IP 地址、工作空间、操作时间。

4. **AC4 - 清理策略保存**：`POST /operate_log/save` 接受 `{ "clean_time": N }` body，将清理天数保存到 `SystemSetting` 表（`type=SettingType.LOG`）。

5. **AC5 - 清理策略查询**：`GET /operate_log/get_clean_time` 返回当前日志保留天数（从 `SystemSetting` 读取），若未设置返回默认值 180。

6. **AC6 - 日志自动清理**：添加定时任务（`APScheduler` cron），每天凌晨按 `clean_time` 配置删除过期的 Log 记录，使用批量删除避免一次性加载全量数据。

7. **AC7 - 版本与权限限制**：所有端点仅在 PE/EE 版本下可用；读取需 `OPERATION_LOG_READ` 权限，导出需 `OPERATION_LOG_EXPORT` 权限，清理策略需 `OPERATION_LOG_CLEAR_POLICY` 权限，均限 ADMIN 角色。CE 版请求返回 403。

8. **AC8 - 日志不可篡改**：审计日志表无 UPDATE/DELETE 业务接口暴露（仅通过定时清理任务按策略删除过期记录），日志本身无面向一般用户的展示通道。

### 关键实现细节

**JSONField 模糊查询**：`user` 字段是 JSONField，按用户名搜索时需使用 Django 的 JSON 查询语法：`Log.objects.filter(user__username__icontains="keyword")`。PostgreSQL 支持此操作。[Source: Django docs - JSONField lookups]

**menu 国际化标签映射**：`@log` 装饰器记录的 `menu` 值是英文原始字符串（如 `"User management"`），前端需要显示国际化标签。实现方案：在 `menu_operation_option` 接口中，对每个 menu 值使用 Django 的 `gettext()` 翻译函数生成 `menu_label`。需要维护一个 menu 值到国际化键的映射。参考 i18n 文件 `apps/locales/zh_CN/LC_MESSAGES/django.po`。

**EE 版 workspace_name 附加**：EE 版返回数据需要附加 `workspace_name` 字段。查询时需 LEFT JOIN workspace 表获取名称。可参考 `application_chat.py:250-257` 中 EE 版使用不同 SQL 文件的模式。简化方案：查询结果后处理，从 Workspace 表按 `workspace_id` 批量查询名称映射。

**Excel 导出参考实现**：严格参照 `apps/application/serializers/application_chat.py:202-248` 的 `export()` 方法模式：`openpyxl.Workbook(write_only=True)` + 分页读取 + `StreamingHttpResponse`。

**定时清理任务参考**：严格参照 `apps/common/job/clean_chat_job.py` 模式：`@lock` 装饰器 + `scheduler.add_job(cron)` + 批量删除循环。

### 陷阱与防护

1. **JSONField 查询性能**：`user__username__icontains` 在大量日志下可能慢。如果日志量超过百万级，考虑在 Log 模型增加 `username` 独立字段并加索引。当前先用 JSONField 查询（与现有模型保持一致，不加字段）。
2. **menu 国际化映射**：`@log` 装饰器中的 `menu` 参数是英文硬编码字符串，需要建立映射表或利用 Django `gettext()` 翻译。前端 `getMenuList` 返回后使用 `ele.menu_label` 显示。
3. **时间范围查询**：前端传递的 `start_time` 格式为 `"YYYY-MM-DD"`（不含时分秒），后端需将 `start_time` 转为当天 00:00:00、`end_time` 转为当天 23:59:59。
4. **export 路由冲突**：`operate_log/export/` 带尾斜杠，`operate_log/save` 不带。务必与前端 API 定义精确匹配。
5. **批量删除安全**：清理任务中的批量删除使用 `[:batch_size]` 分批（参考 `clean_chat_job.py:49-50`），避免长事务锁表。
