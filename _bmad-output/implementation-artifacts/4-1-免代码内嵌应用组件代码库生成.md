# Story 4.1: 免代码内嵌应用组件代码库生成

Status: done

## Story

As a 管理员,
I want 点击一键生成包含如脚本或 iframe 标签的支持内嵌第三方的发行代码片段,
so that 不需改变外部企业现存老旧业务架构，即刻令网页具备浮窗 AI 助手.

## Acceptance Criteria

1. **Given** 我在一个已发布的智能体应用发布页（`application-overview`）下，**When** 我选择发行方式为"嵌入到网站"，**Then** 系统前端需要生成带有相应 APP Access Token 签名认证的可直接复制拷贝的三种嵌入代码串（全屏 iframe、浮窗 JS script、移动端 iframe），**And** 每种代码串均包含正确的 `access_token`。
2. **Given** 应用已开启公开访问（`is_active=True`），**When** 第三方网站加载浮窗 JS script 时，**Then** `GET /chat/api/embed?protocol=...&host=...&token={access_token}` 端点必须返回有效的 JS 内容，**And** 该端点以无状态 Bearer 授权（`access_token` 作为鉴权凭证）处理请求。
3. **Given** 应用的公开访问开关处于关闭状态（`is_active=False`），**When** 用户点击"嵌入到网站"按钮，**Then** 该按钮应处于 disabled 状态，不可点击。
4. **Given** 管理员需要刷新 Access Token，**When** 点击刷新按钮并确认，**Then** 旧 Token 失效，新 Token 自动生成并更新显示，嵌入代码串随之更新。
5. **Given** 访问限制页中管理员配置了 IP 白名单（`white_active=True`，`white_list=[...]`），**When** 不在白名单的 IP 访问嵌入对话页，**Then** 中间件应拒绝该请求。

> **⚠️ 棕地背景说明**：嵌入代码生成的核心基础架构已在生产代码中完整实现。本故事重点是**验证端到端数据流、测试覆盖与潜在缺口修复**，而非从零重写。

### 完整端到端嵌入代码数据流

```
[管理员点击"嵌入到网站"]
        ↓
application-overview/index.vue
  openDialog() → EmbedDialogRef.value.open(accessToken.value?.access_token)
        ↓
EmbedDialog.vue: open(val: string)
  val = access_token (16位 MD5 hash，如 "a1b2c3d4e5f6a7b8")
  ├── source1 = 全屏 iframe (src= application.location + val + urlParams1)
  ├── source2 = 浮窗 JS script (src= application.location + "api/embed?protocol=...&host=...&token=" + val)
  └── source3 = 移动端 iframe (src= application.location + val + "?mode=mobile&...")
        ↓
[用户点击复制按钮]
  copyClick(source1/2/3) → clipboard.ts → navigator.clipboard.writeText()
        ↓
[用户将代码粘贴到第三方网站]

===== 浮窗模式加载流 =====
[第三方网站加载浮窗 JS]
  GET /chat/api/embed?protocol={http/https}&host={domain}&token={access_token}&{api_input_params}
        ↓
ChatEmbedView.get() (apps/chat/views/chat_embed.py)
  → ChatEmbedSerializer({protocol, host}).get_embed(params=request.query_params)
  → 生成包含 token 的浮窗初始化 JS（动态创建 <iframe src=".../{token}"> 并注入到页面）
  → 返回 Content-Type: application/javascript

===== iframe 模式加载流 =====
[浏览器请求 iframe src]
  GET /{chat_prefix}/{access_token}
        ↓
chat_headers_middleware.py
  → 从 path 提取 access_token
  → get_application_access_token(access_token) 查 DB/缓存
  → 校验 is_active、white_active/white_list
  → 注入 application_icon/application_name 到 response headers
        ↓
前端 chat 应用加载（ui/src/chat.ts）
  → 使用 access_token 作为 ChatTokenAuth 凭证发起对话 API 请求
```

#### `AccessTokenSerializer` 核心逻辑摘要

```python
def one(self, with_valid=True):
    """获取或自动创建 access token"""
    application_access_token = QuerySet(ApplicationAccessToken).filter(
        application_id=application_id).first()
    if application_access_token is None:
        # 自动创建：MD5(UUID7)[8:24] → 16位 token
        application_access_token = ApplicationAccessToken(
            application_id=application_id,
            access_token=hashlib.md5(str(uuid.uuid7()).encode()).hexdigest()[8:24],
            is_active=True
        )
        application_access_token.save()
    # 返回 dict（企业版附加 authentication 字段）
    return {'access_token': ..., 'is_active': ..., 'access_num': ..., ...}

def edit(self, instance):
    """修改 access token 设置"""
    if 'access_token_reset' in instance and instance.get('access_token_reset'):
        # 重置 token：生成新的 16 位 MD5 hash
        application_access_token.access_token = hashlib.md5(
            str(uuid.uuid7()).encode()).hexdigest()[8:24]
    # 其余字段按需更新，企业版需检查 license_is_valid
```

### 架构约束与强制规则

参见 `_bmad-output/planning-artifacts/architecture.md`：

1. **通信协议**：嵌入 Widget 与后端通信必须使用 SSE（Server-Sent Events），不得使用 WebSocket。iframe/浮窗 JS 生成的对话界面已遵循此约束。
2. **鉴权模式**：
   - 管理员端（概览页）：使用 Session + Bearer Token（管理员账号登录）
   - 嵌入对话端（embed widget）：使用 `access_token` 作为无状态匿名鉴权凭证（`ChatTokenAuth`）
   - 开放 API 端（`/api/v1/openapi`）：使用 `ApplicationApiKey.secret_key`（Bearer Token）
3. **前端 API 封装**：所有 HTTP 请求必须通过 `ui/src/api/` 下的封装函数，不得在 Vue 组件内裸写 axios 调用。
4. **loading 状态**：所有异步操作必须挂载 `loading.value = true`，通过 Axios 拦截器自动处理。
5. **API 响应格式**：后端必须返回标准封套 `{"code": 200, "message": "success", "data": {...}}`。
6. **snake_case**：所有后端字段（`access_token`, `is_active`, `white_active`, `white_list`）均为下划线命名，前端 `application.ts` 直接映射，无需 camelCase 转换。
7. **Token 安全**：`access_token` 为 16 位 MD5 hash（`hashlib.md5(str(uuid.uuid7()).encode()).hexdigest()[8:24]`），不得硬编码，不得在前端 localStorage 中存储管理员 API Key。

### 关键风险与注意事项

1. **`application.location` 变量**：`EmbedDialog.vue` 使用 `useStore().application.location` 来拼接 URL。需确认 `stores/` 中 `application.location` 的值在生产/开发/Docker 环境下的正确性（通常为 `window.location.origin + "/"` 或后端配置）。
2. **`urlParams` 的拼接规则**：
   - `urlParams1`：`?key=value&...`（用于全屏 iframe，作为 query string 第一个参数）
   - `urlParams2`：`&key=value&...`（用于浮窗 JS，接在 `token=xxx` 后）
   - `urlParams3`：`?mode=mobile&key=value&...`（用于移动端 iframe）
   当 `apiInputParams` 为空时，三者均为空字符串，不应出现多余 `?` 或 `&`。
3. **`chatPrefix` 配置**：`window.MaxKB.chatPrefix` 是系统运行时注入的前缀（如 `/chat`），必须与后端 `CONFIG.get_chat_path()` 保持一致。
4. **Token 刷新后旧 Token 失效**：刷新 token 后，已嵌入旧 token 代码的第三方网站将失效，需要重新复制新代码。这是预期行为，但建议在 UI 提示中说明。
5. **浮窗 JS 的 CORS**：`GET /chat/api/embed` 端点被第三方网站跨域加载，需确认 Django 的 CORS 配置（`CORS_ALLOW_ALL_ORIGINS` 或白名单）允许此端点的跨域访问。
6. **`allow="microphone"`**：iframe 的 `allow="microphone"` 属性允许语音输入功能（若应用集成了 STT），这是系统设计意图，不应移除。

            is_active=True

        ).edit({'access_token_reset': True})
        self.assertNotEqual(result['access_token'], 'oldtoken1234567')
        self.assertEqual(len(result['access_token']), 16)
