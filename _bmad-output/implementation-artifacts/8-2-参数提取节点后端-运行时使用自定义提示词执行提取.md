# Story 8.2: 参数提取节点后端 - 运行时使用自定义提示词执行提取

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 编排工程师,
I want 配置了自定义提示词的"参数提取"节点在工作流执行时，使用我编写的提示词而非系统默认提示词来调用大模型,
so that 参数提取的行为和结果完全按照我的业务场景定制的指令执行.

## Acceptance Criteria

1. **Given** "参数提取"节点的 `node_data` 中存在 `prompt_type == 'custom'` 且 `custom_prompt` 非空
   **When** 工作流执行到该节点、`execute()` 方法被调用时
   **Then** 后端应使用 `custom_prompt` 替代模块级默认 `prompt` 常量，通过 `PromptTemplate.from_template()` 渲染模板（仍支持 `{{question}}` 和 `{{properties}}` 变量）

2. **And** 若 `prompt_type == 'system'`（或该字段不存在），行为与改动前完全一致，使用系统默认提示词

3. **And** 若 `custom_prompt` 为空字符串或 None，即使 `prompt_type == 'custom'`，也应回退使用系统默认提示词，不抛出异常

4. **And** 改动仅限于 `apps/application/flow/step_node/parameter_extraction_node/impl/base_parameter_extraction_node.py`，不修改其他节点类型的处理逻辑

### 核心架构理解（必读）

#### 为什么不需要修改序列化器 `VariableSplittingNodeParamsSerializer`

`INode.__init__` 中：
```python
def __init__(self, node, workflow_params, workflow_manage, up_node_id_list=None,
             get_node_params=lambda node: node.properties.get('node_data'), salt=None):
    self.node_params = get_node_params(node)  # ← self.node_params 就是完整的 node_data dict
    ...
    self.node_params_serializer = None  # 后续由 valid_args() 设置
```

`self.node_params` **直接等于** `node.properties.get('node_data')`，即前端存储的完整 `node_data` 字典，包含 `prompt_type` 和 `custom_prompt`。

序列化器 `VariableSplittingNodeParamsSerializer` 仅用于验证并提取出已知字段（`input_variable`、`variable_list`、`model_params_setting`、`model_id`）供 `_run()` 调用，不影响 `self.node_params` 的完整性。

因此，在 `execute()` 中直接访问 `self.node_params.get('prompt_type')` 即可获取前端 Story 8.1 保存的字段，**无需修改接口文件或序列化器**。

#### 数据流路径（端到端）

```
前端(Story 8.1) → node_data = { prompt_type: 'custom', custom_prompt: '...', ... }
        ↓ 持久化到工作流定义
后端运行时:
  INode.__init__: self.node_params = node.properties.get('node_data')
        ↓
  IParameterExtractionNode._run():
    序列化器验证 input_variable / variable_list / model_params_setting / model_id
    调用 self.execute(input_variable, variable_list, ...)
        ↓
  BaseParameterExtractionNode.execute():
    self.node_params.get('prompt_type', 'system')  ← 读取 prompt_type
    self.node_params.get('custom_prompt', '')       ← 读取 custom_prompt
    effective_prompt = custom_prompt if (prompt_type == 'custom' and custom_prompt) else prompt
    generate_content(input_variable, variable_list, effective_prompt)
```

#### 改动后（最终目标代码）

```python
# generate_content 新增可选参数 prompt_template_str（向后兼容）
def generate_content(input_variable, variable_list, prompt_template_str=prompt):
    properties = generate_properties(variable_list)
    prompt_template = PromptTemplate.from_template(prompt_template_str, template_format='jinja2')
    value = prompt_template.format(properties=properties, question=input_variable)
    return value


def execute(self, input_variable, variable_list, model_params_setting, model_id, **kwargs) -> NodeResult:
    input_variable = str(input_variable)
    self.context['request'] = input_variable
    if model_params_setting is None:
        model_params_setting = get_default_model_params_setting(model_id)
    workspace_id = self.workflow_manage.get_body().get('workspace_id')
    chat_model = get_model_instance_by_model_workspace_id(model_id, workspace_id,
                                                          **model_params_setting)
    # 读取自定义提示词配置（self.node_params 即完整 node_data，无需修改序列化器）
    prompt_type = self.node_params.get('prompt_type', 'system')
    custom_prompt_text = self.node_params.get('custom_prompt', '')
    # custom_prompt 为空或非 custom 模式时，安全回退到系统默认提示词
    effective_prompt = custom_prompt_text if (prompt_type == 'custom' and custom_prompt_text) else prompt
    content = generate_content(input_variable, variable_list, effective_prompt)
    response = chat_model.invoke([HumanMessage(content=content)])
    result = json_loads(response.content, variable_list)
    return NodeResult({'result': result, **result}, {})
```

### 关键实现细节

#### `self.node_params` 类型保证

`self.node_params = node.properties.get('node_data')` 返回一个 `dict`（或 `None`）。
Story 8.1 前端保存的 `node_data` 始终包含 `prompt_type` 和 `custom_prompt`，但：
- **旧节点**（Story 8.1 上线前创建）：`node_data` 中无这两个字段
- 因此必须使用 `.get('prompt_type', 'system')` 和 `.get('custom_prompt', '')` 的默认值形式

如果 `self.node_params` 为 `None`（极端异常情况），`.get()` 会抛 `AttributeError`。但经过 `valid_args()` 验证后，serializer 会在 `node_params` 为 None 时提前抛错，所以此处不会为 None。

#### 回退逻辑一览

| `prompt_type` | `custom_prompt` | 实际使用提示词 |
|---|---|---|
| `'system'`（或字段不存在） | 任意 | 系统默认 `prompt` 常量 |
| `'custom'` | 非空字符串 | `custom_prompt` |
| `'custom'` | `''`（空字符串） | 系统默认 `prompt` 常量（安全兜底） |
| `'custom'` | `None` | 系统默认 `prompt` 常量（`and custom_prompt` 为 False） |

#### 系统默认 prompt 常量内容（第 21-37 行，勿改动）

```python
prompt = """
Please strictly process the text according to the following requirements:
**Task**:
Extract specified field information from given text

**Enter text**:
{{question}}

**Extract configuration**:
{{properties}}

**Rule**:
- Strictly follow the data and field of Extract configuration
- If not found, use null value
- Only return pure JSON without additional text
- Keep the string format neat
"""
```

`{{question}}` 和 `{{properties}}` 是 Jinja2 模板变量（`template_format='jinja2'`），自定义提示词亦需使用相同占位符格式。

| 场景 | 分析 | 风险 |
|---|---|---|
| 旧节点（无 `prompt_type` 字段） | `.get('prompt_type', 'system')` 返回 `'system'`，使用系统默认提示词 | 无 |

| `prompt_type: 'custom'` 且 `custom_prompt` 为空 | 条件 `custom_prompt_text` 为 falsy，回退系统默认 | 安全兜底 |
| 其他节点类型 | 改动仅在 `base_parameter_extraction_node.py`，完全隔离 | 无 |
| `generate_content` 向后兼容 | 新增参数使用默认值，现有调用无需修改 | 无 |
