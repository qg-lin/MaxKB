# Story 5.3: 全渠道触达之三方 IM 系统连接

Status: done

## Story

As a 管理员,
I want 能将已经编辑完备并测试可行的单一智能体机器人挂载到类似企业微信、钉钉、飞书、微信公众号及 Slack 等渠道当成机器人帐号回应发问,
so that 公司使用员工完全不需要专门安装额外的网站就能在工作聊天框里完成问答操作.

## Acceptance Criteria

1. **AC1 - 渠道配置 CRUD**：管理员在应用的"渠道接入"页面下，对 6 种平台（企微应用、企微机器人、钉钉、微信公众号、飞书、Slack）分别填入平台凭证后保存，`POST /workspace/{wid}/application/{aid}/platform/{type}` 返回 200，配置持久化到 `ApplicationPlatform` 表。

2. **AC2 - 配置回显与状态查询**：`GET /workspace/{wid}/application/{aid}/platform/{type}` 返回已保存配置（敏感字段掩码）；`GET /workspace/{wid}/application/{aid}/platform/status` 返回各平台 `[exists, isActive]` 状态字典。

3. **AC3 - 平台启停控制**：`POST /workspace/{wid}/application/{aid}/platform/status` 传入 `{type, status}` 能正确切换平台的启用/禁用状态。

4. **AC4 - Webhook URL 验证**：各 IM 平台首次配置 webhook 时发起的 URL 验证请求（GET 类型的 token/signature 校验），后端能正确响应验证挑战（如微信的 echostr 回显、钉钉的签名验证、飞书的 challenge 响应等）。

5. **AC5 - 消息接收与转发**：IM 平台用户发送文本消息后，webhook 端点接收 POST 请求，正确解析消息体，调用对应应用的对话引擎（`ChatSerializers`），获取 AI 回复。

6. **AC6 - 异步回复推送**：AI 回复生成完毕后（流式聚合或阻塞等待），通过各平台提供的消息发送 API 将回复文本推回给发起提问的用户/群聊，且 chat_record 的 `source` 字段正确记录为对应平台枚举值。

7. **AC7 - 版本限制**：IM 渠道接入功能仅在 PE/EE 版本生效。CE 版请求平台配置接口时返回 403 或功能未启用提示。

## Dev Notes

### 架构关键约束

- **版本守卫**：`apps/maxkb/settings/base/web.py` 中 `edition = 'CE'`（CE 版）。IM 渠道接入是 PE/EE 专属能力。在视图层入口校验 `from maxkb import settings; settings.edition` 是否为 `'PE'` 或 `'EE'`，CE 版直接返回错误响应。参照 Story 5-1 的实现模式。
- **Webhook 免鉴权**：IM 平台的 webhook 回调不走系统 Bearer Token 认证。使用已有的 `WebhookAuth`（返回空认证对象），安全性由各平台自身的签名验证机制保障。[Source: apps/common/auth/authenticate.py]
- **CSRF 豁免**：所有 webhook 视图必须添加 `@csrf_exempt` 装饰器，否则外部 POST 请求会被 Django CSRF 中间件拦截返回 403。
- **回调 URL 格式**：前端 `AccessSettingDrawer.vue` 第 443 行硬编码了回调 URL 格式为 `${origin}${prefix}/api/chat/${type}/${application_id}`。后端路由必须严格匹配此模式。[Source: ui/src/views/application/component/AccessSettingDrawer.vue#L443]
- **Celery 异步回发**：webhook 端点必须在 3-5 秒内响应 200（各 IM 平台超时限制），因此 AI 对话调用和消息回发必须通过 Celery `@shared_task` 异步执行，webhook 视图立即返回空响应或平台要求的确认格式。
- **命名规范**：后端 snake_case（`app_id`、`app_secret`、`client_secret`），前端 API 传递也保持 snake_case（前端已按此格式发送/接收）。[Source: _bmad-output/planning-artifacts/architecture.md#命名模式]
- **ChatSourceChoices 已定义**：`apps/application/models/application_chat.py` 第 68-78 行已有全部 IM 平台枚举值（ENTERPRISE_WECHAT, WECHAT_PUBLIC_ACCOUNT, LARK, DINGTALK, ENTERPRISE_WECHAT_ROBOT, SLACK），直接复用，无需新增。[Source: apps/application/models/application_chat.py#L68-L78]

### Webhook 验证机制速查

**企微应用/机器人** (GET 验证)：
- 收到 `msg_signature`, `timestamp`, `nonce`, `echostr` 参数
- 使用 `token` + `encoding_aes_key` 解密 echostr 并回显明文
- 推荐使用 `WXBizMsgCrypt` 库（企微官方 Python SDK）

**钉钉** (POST 内含签名)：
- Header 中包含 `timestamp` + `sign`
- sign = Base64(HMAC-SHA256(timestamp + "\n" + app_secret))
- 验证通过后解析 JSON body

**微信公众号** (GET 验证)：
- 收到 `signature`, `timestamp`, `nonce`, `echostr`
- signature = SHA1(sort([token, timestamp, nonce]))
- 验证通过后回显 echostr
- POST 消息体为 XML 格式

**飞书** (POST challenge)：
- 收到 `{"challenge": "xxx", "token": "verification_token", "type": "url_verification"}`
- 响应 `{"challenge": "xxx"}`
- 后续事件通过 `im.message.receive_v1` 类型推送

**Slack** (POST challenge + 签名)：
- URL 验证：收到 `{"type": "url_verification", "challenge": "xxx"}`，响应 `{"challenge": "xxx"}`
- 消息签名：Header `X-Slack-Signature` = `v0=` + HMAC-SHA256(signing_secret, `v0:timestamp:body`)
- 消息事件类型：`event_callback` 内 `event.type == "message"`

### 异步处理架构要点

```
IM 平台 POST /api/chat/{type}/{app_id}
    │
    ▼
Webhook 视图 (同步, <3s)
    ├─ 验证签名/token
    ├─ 解析消息 (提取 user_id, text)
    ├─ 立即返回 200（或平台要求的空响应/被动回复格式）
    └─ 提交 Celery 异步任务 ──►
                                  │
                                  ▼
                        Celery Worker (异步)
                            ├─ 查找 ApplicationPlatform 配置
                            ├─ 查找/创建 Chat 会话
                            ├─ 调用 ChatSerializers.chat(stream=False)
                            ├─ 获取完整 AI 回复文本
                            └─ 调用平台回发 API 推送消息
```

**微信公众号特殊处理**：微信公众号支持"被动回复"模式——如果 AI 能在 5 秒内生成回复，可直接通过 HTTP response 返回 XML 格式消息，无需额外调用 API。建议先尝试被动回复（设置合理超时），超时则回复"正在思考中..."并通过客服消息 API 异步推送最终回复。

### 关键依赖库

- **企微消息加解密**：`WXBizMsgCrypt3`（企微官方 Python3 SDK）或自实现 AES-CBC 解密——检查 `pyproject.toml` 是否已有，否则需新增
- **XML 解析**：使用 Python 标准库 `xml.etree.ElementTree`（已内置，无需额外依赖）
- **HTTP 调用第三方 API**：使用 `requests` 库（`pyproject.toml` 中已有）
- **HMAC 签名**：使用 Python 标准库 `hmac` + `hashlib`（已内置）

### 与 Story 5-1 的关联

Story 5-1 实现了 SSO 认证体系（LDAP/OIDC/CAS/OAuth2/SAML2 + 企微/钉钉/飞书扫码登录）。本 Story 与其的关键区别：
- 5-1 是**系统级**身份认证配置（存储在 `SystemSetting` 表）
- 5-3 是**应用级**渠道接入配置（每个应用可独立配置不同的 IM 渠道）
- 5-1 的扫码配置（企微 corp_id/agent_id 等）是**登录用途**
- 5-3 的企微配置是**消息接收/发送用途**，两者可以使用不同的应用凭证
- 不要复用 5-1 的 SystemSetting 存储模式，本 Story 应使用独立的 `ApplicationPlatform` 模型

### 已有触发器(Trigger)机制对比

`apps/trigger/` 实现了事件触发器的 webhook 机制（`EventTriggerView`），但**不建议复用**：
- Trigger 是通用的事件触发框架，与具体 IM 平台无关
- IM webhook 需要平台特定的签名验证和消息格式解析
- IM 消息回发需要平台专属 API 调用
- 但可参考 Trigger 的 `WebhookAuth` 免鉴权模式和 `ApplicationTask` 的对话引擎调用模式
