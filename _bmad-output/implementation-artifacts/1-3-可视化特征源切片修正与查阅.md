## Story

As a 库运维员,
I want 可在 WebUI 界面中搜索、阅读那些经过系统拆分的"块碎段"并编辑其文本与引用源标记,
so that 能在系统切分不完美时人为修正数据，以保证问答时引用的片段精确无误.

1. **Given** 某份被向量化完毕的文档详情页中
   **When** 我点击"文档切片"列表页卡时
   **Then** 系统应从库中调取出对应的分段列表，并允许我对文本及其源元数据进行 Update 覆盖
   **And** 保存修正时不得破坏已存在的 pgvector 索引结构

class Paragraph(AppModelMixin):

### ⚡ pgvector 安全机制（核心约束）

**绝对禁止直接修改 `embedding` 表！** 编辑段落后必须走以下流程：

```python
# apps/knowledge/serializers/paragraph.py - Operate.edit() 方法
# 使用 @post(post_embedding) 装饰器，编辑后自动触发 re-embedding
@post(post_embedding)  # ← 这个装饰器确保 pgvector 安全更新
@transaction.atomic
def edit(self, instance: Dict):
    # 修改 Paragraph ORM 对象
    _paragraph.save()
    # 返回后 post_embedding 自动调用 embedding_by_paragraph()
```

**re-embedding 逻辑**（`post_embedding` 静态方法）：
```python
@staticmethod
def post_embedding(paragraph, instance, knowledge_id):
    if 'is_active' in instance and instance.get('is_active') is not None:
        # 仅切换启用状态 → 调用 enable/disable_embedding_by_paragraph
        (enable_embedding_by_paragraph if instance.get('is_active')
         else disable_embedding_by_paragraph)(paragraph.get('id'))
    else:
        # 文本内容修改 → 完整 re-embedding（通过 models_provider 调用 Embedding 模型）
        model_id = get_embedding_model_id_by_knowledge_id(knowledge_id)
        embedding_by_paragraph(paragraph.get('id'), model_id)
```

**前端调用规范**：
- 编辑保存必须调用 `PUT /paragraph/{paragraph_id}` 而非直接操作数据库
- 不得绕过序列化器层修改 `Embedding` 表
- `chunks` 字段（ArrayField）是源标记数组，修改后也需触发 re-embedding

## Dev Notes

### 棕地工程最重要原则
- **先读代码，再动键盘**：本 Story 的所有后端功能已存在。首先在浏览器中打开文档详情页，观察"切片"Tab 是否可用，缺什么补什么
- **只改需要改的**：不要重构 `ParagraphList.vue`，只要接线缺失的 API 调用即可
- **pgvector 永远通过序列化器更新**：任何段落内容修改必须走 `PUT /paragraph/{id}`，绝不直接操作 `Embedding` 模型

### 性能注意事项
- 文档可能有数千个段落，**严禁一次性全量加载**，必须使用分页 API（`/paragraph/{current_page}/{page_size}`）
- 搜索操作加 300ms debounce 防止频繁 API 调用
- 编辑完后 re-embedding 是 Celery 异步任务，UI 需有"重新向量化中"的状态提示（可参考 `State.PENDING` 状态）

### pgvector 安全边界
编辑段落的安全操作链：
```
前端 PUT → Django View → Serializer.Operate.edit()
  → _paragraph.save() (ORM)
  → @post(post_embedding) 装饰器
  → embedding_by_paragraph(paragraph_id, model_id)  ← Celery 异步
  → 从 models_provider 获取 Embedding 引擎
  → 更新 Embedding 表中对应 source_id 的向量记录
```
这条链路保证了 pgvector 索引的完整性。前端只需调用 PUT API，后端自动处理。
